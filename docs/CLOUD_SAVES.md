# アカウント別クラウド保存

## 保存と移行

Web版は `user://profiles/guest.json` と `user://profiles/<account UUID>.json` を分離します。
従来の `save.json` は削除せず、最初にゲスト枠へ移します。ログイン済みでも、自動的にそのアカウントへ帰属させません。
最初のクラウド保存時に「ゲストの進行を引き継ぐ」「新しく始める」を選びます。
引き継ぎ元をローカルにバックアップし、クラウドへの送信成功後にゲスト枠を新規状態へ戻します。失敗中は元のゲストを残します。
既存クラウドとゲストの両方があるときは比較して選択します。ポイント、実績報酬、ランの状態を合算しません。

通常・無限・アリーナの途中状態、メタポイント、解放、永続強化、実績・受取状態を保存します。
通常戦闘の途中では、キャラクターの実行中エンジンではなく戦闘開始前のチェックポイントを共有します。
進行中のWeb対戦の端末間移動は対象外です。ランキングの正式得点にはクラウド申告値を使用しません。
GoogleとGitHubは今までどおり別アカウントで、アカウント間の共有や連携は追加しません。

音量・言語・解像度・開発者設定・リプレイ保存先・送信待ちランキングは端末設定として分離します。
開発者権限はサーバー側の許可リストで判定し、保存データで付与できません。
Godot実行版は従来のローカル保存を維持します。クラウドに対応するのは現在ログイン機能のあるWeb版です。

## 同期とログアウト

ローカルを即時に保存し、変更後にクラウドへ非同期で送信します。画面には同期済み・送信待ち・オフラインを表示します。
初期取得失敗では空データをクラウドへ書きません。通信障害をログアウトとして扱いません。
明示的なログアウトまたは確定した認証切れでは、旧アカウント用キャッシュを保存してゲストに切り替えます。
未送信時の明示ログアウトでは、再試行または端末に保留したままログアウトするか選択します。
認証サーバー自体に接続できない間はログアウト完了扱いにせず、接続後の再試行が必要です。
ログアウトはクラウドやアカウント用のキャッシュをゲスト枠へコピーしません。他人が使うPCではブラウザのサイトデータも管理してください。
キャッシュは端末上の暗号化保管庫ではありません。

クラウドには単調増加するrevisionがあり、DBトランザクションで一致した更新だけを受け入れます。
1タブごとのランダムなwriter IDに50秒の操作権を与え、15秒ごとに更新します。
他の端末へ移るときは明示的に操作権を引き継ぎます。旧端末の書き込みは拒否し、そのデータは保留します。
競合時は両方を保護してクラウド／端末のどちらを使うか選びます。PC時計による新しさ判定や自動上書きはしません。
端末の退避データもアカウントごとに直近10件保持し、アカウントパネルから復元できます。
同一内容の送信再試行はrequest UUIDで冪等化します。

## サーバー

既存の認証セッションと非公開PostgreSQLを使用し、追加のサービス契約はありません。
`qq_cloud_saves` に最新データ、`qq_cloud_save_history` に直前5世代を保存します。最新とは別に5件です。
1データ4 MB、JSON階層48、25万ノードまでです。上限超過は送信エラーとしてローカルへ保持します。
クラウドのschema_versionは現在1です。互換性のない保存形式変更では、クライアント・サーバーの移行とバージョン判定を同時に更新してください。
所有者はCookieから決め、リクエストの期待アカウントIDと照合します。アカウント切替中の旧リクエストを別アカウントへ保存しません。
書き込みにはOrigin、CSRF、操作権、世代を要求します。非公開・no-storeとし、R2の公開バケットには保存しません。
通常進行のクラウド保存は改造対策・正式ランキングの根拠ではありません。正式スコアは既存の操作再生検証でのみ計算します。

## ゲーム内画面

アカウントとランキングは同じページ内の再利用可能なiframeパネルに表示します。クロスオリジンの埋め込みは禁止し、同一オリジンのみ許可します。
Google/GitHubへの認証だけ別の認証ウィンドウを開き、完了後に閉じてゲーム内の登録・保存管理へ戻ります。
パネルのメッセージは送信元オリジンと、そのパネルのcontentWindowの両方を照合します。

## 検証

`server/cloud/cloud.test.js` は使い捨ての実PostgreSQL上で所有者・CSRF・世代競合・旧端末拒否・再送・履歴復元を検証します。
`CloudProfileSmoke` は旧セーブ維持、ゲスト・アカウント分離、端末設定、チェックポイントを検証します。
`tools/web_cloud_review.mjs` は独立したブラウザコンテキストで引き継ぎ、ログアウト、別アカウント、別端末、通信中断と再起動後の競合解決を検証します。API部分は明示的なテスト用モックで、DBテストと組み合わせます。
