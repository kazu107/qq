# LANマルチプレイ仕様

## 対象

- 同一LAN内のWindows PC 2台による1対1アリーナ対戦。
- Godot標準の`ENetMultiplayerPeer`をUDPで使用する。
- 対戦用ポートは既定`32475/UDP`、ロビー検出用ポートは`32476/UDP`。
- メタ進行や永続強化を適用せず、カードと遺物は解放状況に関係なく出現する。

## 接続フロー

1. ホストがプレイヤー名、スターター、UDPポートを指定してLobbyを作成する。
2. クライアントはLAN検出一覧またはホストのIPv4アドレスから参加する。
3. プロトコルバージョンとコンテンツSHA-256を照合する。
4. 両者がアリーナ準備を完了すると戦闘画面へ遷移する。
5. 両者が戦闘開始を押すと3秒カウントダウンし、ホストが戦闘を開始する。
6. ラウンド終了後、勝利側は報酬を選び、両者が次の準備フェーズへ戻る。

## 同期モデル

- ホストが戦闘時間、カード解決、状態効果、勝敗、ショップ操作、ロードアウトを検証する。
- クライアントは操作コマンドだけを送り、ホストの結果とスナップショットを反映する。
- 通常スナップショットは`unreliable_ordered`、重要イベントと再同期は`reliable`を使用する。
- クライアントの表示は最大0.18秒補間するが、ゲームルールを予測実行しない。
- 切断時はホストが15秒間席を保持し、トークンによる自動再接続を受け付ける。

## オンライン版との共通化

オンライン版は現在一時停止中。LAN版はGodot標準の`ENetMultiplayerPeer`だけを使用し、EOS SDK、Client Secret、トークンがないcloneでも動作する。再開用の設計は`docs/ONLINE_MULTIPLAYER.md`を参照する。

## テスト

- `tests/LanMultiplayerSmoke.tscn`: プロトコル、データ不一致拒否、UI、ホスト生成を検証する。
- `tests/validate_lan_network.ps1`: 2プロセスでLobby、準備、戦闘、再接続、報酬を検証する。
- `tests/validate_lan_network_soak.ps1`: 長時間のスナップショット容量と通信安定性を検証する。
- `tests/validate_project.ps1`: 上記を含むプロジェクト全体の検証を行う。

Windows Defender Firewallの確認が表示された場合は、プライベートネットワークでGodotまたは配布ゲームのUDP通信を許可する。LAN版をインターネットへ直接ポート転送しない。
