# 分岐・合流型ノードマップ

QQ-0.37.1 / 2026-10-15 / graph_version=2

## 進行

通常ランは7ステップごとに1区画を表示し、最後のボスへ合流します。既存の7・14・21・28ステップの解放条件は変更していません。無限モードも28ステップ単位で追加し、前周期の最後のボスと次周期の入口を接続します。

各段の候補数は下から **3・4・5・4・5・4・1**。1区画の表示ノードは18個から26個へ増やしました。実際に選んで進む段数は7のままです。通常戦闘・回復による安全な選択、エリート・危険地帯による挑戦、ショップ・鍛冶・イベントによる強化を組み合わせます。入口の通常戦闘は可能な限り異なる敵を選びます。同じ種類のノードでも、その先の接続が異なります。接続は次の段だけを指し、分岐・合流し、必ず最後のボスへ到達できます。全ノードに入口があり、途中で行き止まりにはなりません。

次の段がボス1体の場合を除き、各ノードから最低2本、一部は3本の接続があります。左右端でも隣接候補を内側へ補うため、右端を選び続けても途中から1択にはなりません。段の幅が増減しても接続先を比率で対応付け、入口のない候補が残れば接続を補います。現在地からつながる候補だけを解放します。画面でボタンを無効化するだけでなく、`Game.select_map_node` でも段・接続・状態・処理中ノードを確認します。連打による二重選択や、別ルートの候補への直接アクセスは拒否します。

同じseedと解放段階からは同じ配置・接続・候補を生成します。敵抽選、追加候補、左右反転、位置の微調整、斜めの接続方向で変化を付けます。既存の種類やボスを削除せず、中間段に通常戦闘・回復・イベントの候補を追加しました。

## 表示

地図は下から上へ進む2D表示です。既存のBlender製マップアイコンを再利用し、時計の目盛り・曲線の道をUIとして描画します。未来のノードは種類と名前を薄く表示し、進める候補を発光、通過した道を金色、現在地を追加の輪で示します。ホバーではその先につながる道と説明を表示します。未来のノードを錠前で覆わず、次の未解放区画だけを錠前で示します。

横長画面は地図を約7割、ロードアウトを右側に配置します。縦長画面は地図を優先し、ロードアウトをボタンから開くウィンドウへ移します。5列でも選択領域が重ならないよう、横方向の配置幅を広げ、各段のノード間隔に合わせてボタン幅を調整します。7段階の間隔とノードの表示密度を画面に合わせ、初回・帰還・区画切り替えでは現在の経路へスクロールします。ノード選択時は約0.28秒で駒が移動してからシーン遷移します。最終的な選択が拒否された場合、駒は元の位置へ戻します。

ラン履歴はボタンから開くウィンドウへ移しました。内容は開くときに構築し、戦闘履歴が変わらない間は再利用します。地図のノードと接続形状も、進行・区画・画面サイズが変わらない限り再利用します。既存の起動時アイコンキャッシュを共有し、3Dモデルの先読みは実際に選択可能な敵だけに限定します。Escで履歴・ロードアウトを閉じられます。

## セーブとスコア

ノードのID、候補、状態、`next_ids`、`map_x`、`graph_version` を既存の `map_state` に保存します。旧セーブでは通過済みの段を増やさず、現在以降の未選択部分だけに候補を追加します。戦闘・施設の処理中ならその段も変更せず、次の段から増やします。既に提示されている候補・選択・経過済みの経路・購入済み商品を保持し、新しい分岐ルールを適用します。無限モードの追加ノードにも周期と強化段階を引き継ぎます。旧ランを再生成したり、所持カードや遺物を変更したりしません。

戦闘効率では、選択済みの経路と両立する将来の経路を後ろから計算し、未戦闘分を分母へ含めます。各段の最安候補を独立に足して到達できない経路を想定したり、分岐の全候補を重複加算したりしません。旧形式や不完全な検証用データには従来の集計を残し、アリーナの計算は変更していません。

## 開発・検証

開発者パネルの「経路テスト：次へ（戦闘省略）」で、次の接続候補と区画遷移を確認できます。通常の戦闘報酬・戦闘実績は付与しません。遺物のステップ進入効果と無限周回補正は通常どおり動作します。開発者モードが無効、処理中ノードがある、またはアリーナ中の場合は使用できません。

`NodeMapSmoke` は320通りのseed・解放段階の再現性、各区画26ノード、ボス前以外の最低2分岐と3分岐の生成、ノード重複・入口・行き止まり・不正接続、56ステップの無限周期、旧セーブ移行・購入済み商品・周期強化情報、接続検証と二重入力、経路に沿ったスコア、開発者進行、履歴の遅延構築を確認します。既存の施設・段階解放・スコア・セーブ継続のテストも対象です。

`tools/web_node_map_review.mjs` は Web Layout Review 出力を実ブラウザで確認します。1440×900・960×600・900×1200で26ノード、選択領域の非重複、左右端を連続して選ぶ経路、現在地、接続候補、履歴、ロードアウト、区画切り替えとボスゲートを確認し、実際のクリックから移動演出を経て戦闘へ遷移することも確認します。今回のログは `tools/.local/node-map-branch-tests`、画像とブラウザ結果は `tools/.local/node-map-browser` に出力します。

2026-10-15の検証では、NodeMapSmoke、MapFacilitySmoke、RunScoreSmoke、ProgressionTierSmoke、SaveContinueSmoke、ArenaFlowSmokeと上記ブラウザ検証が成功しました。汎用FlowSmokeの初回タイムアウトは、戦闘後に表示される結果画面で「続行」を押さない古いテスト手順が原因でした。現在は勝利・敗北演出の完了と結果表示を確認してから続行を押し、Rewardへの遷移が成功しています。公開版の動作確認はローカル検証と別に行います。

## 後半区画のイベント

絶対エリア番号に対応した専用イベントがない場合は、区画内の1〜3番目に対応する既存イベントを用います。未出現イベントを優先し、候補を使い切った場合は同じ対象プールから再抽選します。専用のエリア番号や明示的な既定値があればそちらを優先し、`base/per_area`の計算は実際のエリア番号を維持します。1〜3だけの`by_area`表には区画内の番号を適用し、後半区画で回復量が0になることを防ぎます。

空の選択肢を保存した古いイベントは、表示時に一度だけ生成して保存します。既知のイベントIDは維持し、すでに有効な選択肢や報酬候補は再抽選しません。コンテンツを取得できない場合にも、イベントの報酬・効果を適用せず先へ進む選択肢を表示します。EventProgressionSmokeはエリア1〜60、使用済み候補、専用データ優先、値の計算、実際の第2区画、セーブ復旧・再読込・再抽選防止・二重報酬防止・空コンテンツ退出を確認します。ブラウザテストでも通常・空の旧セーブ・空コンテンツを横長と縦長で開き、表示と選択後のマップ進行を確認します。
