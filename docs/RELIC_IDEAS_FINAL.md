# 新規遺物案 最終整理

- 調査日: 2026-07-12
- 対象: 通常ラン、危険地帯、アリーナ、無限モード
- 調査方法: 既存34遺物のコード監査と、4系統の並行ゲーム調査
- 生案: 132件
- 統合後: 52件

数値は初回プロトタイプ用であり、バランステスト後に調整する。既存遺物に多い「取得時の基礎能力増加」「戦闘開始時の固定シールド・攻撃・速度・詠唱短縮」「勝利時の固定回復・ゴールド」は新案の主効果から除外した。

## 1. 既存遺物の監査結果

既存34遺物は、実装上11種類の単純な操作へ集約できる。

| 系統 | 既存の内容 |
| --- | --- |
| 取得時 | 最大HP、攻撃、速度、ロードアウト上限、ゴールド |
| 戦闘開始時 | シールド、攻撃、速度、全カード詠唱倍率 |
| 勝利時 | HP回復、ゴールド |

現状はカード投入・解決・中断、シールドの自然減衰・完全防御、状態異常の付与・解除・自然終了、timelineの実効移動量、active slotの占有変化、Grade順、モード進行を参照する遺物がない。

### 実装前に直すべき不整合

1. `rift_compass` と `pulse_injector` はどちらも戦闘開始時速度+2だが、アリーナ価格帯が異なる。
2. `armor_garden` は取得時に最大HPと現HPを4増やすが、ツールチップは現HP回復を説明していない。
3. LANアリーナの勝利処理は `apply_victory_bonuses()` を通らず、勝利時効果を持つ9遺物が発動しない。
4. `relics.json` は表示情報だけで、効果は `RelicService.gd` のID分岐へ固定されている。データと実効果がずれても検出できない。
5. LAN整合性ハッシュは `relics.json` を含むが `RelicService.gd` を含まないため、コードだけ異なるクライアントを検出できない。

## 2. 調査から採用した設計原則

- Slay the Spire型: 第N回、初回限定、待機報酬、強い利益と明示的な制約。
- Monster Train型: カード種別や行動を追加発火へ変換し、容量と反復をビルド軸にする。
- Wildfrost型: 1枚のカードを選んで改造し、利益と欠点を同時に付ける。
- Risk of Rain 2型: スタックに上限・逓減・発動係数を設け、無限連鎖を防ぐ。
- Dead Cells型: 限られた枠、低HP帯、被弾後の短い回復窓、現在の危険と将来報酬の交換。
- Backpack Hero型: 単品の固定値より、並び・空き・接続・連鎖規則を価値にする。
- Chrono Ark / One Step From Eden型: 状態、Countdown、最初の1回、自動発動を明確な上限付きで扱う。

参考: [Slay the Spire Relics](https://slaythespire.wiki.gg/wiki/Relics)、[Monster Train Artifacts](https://monster-train.fandom.com/wiki/Artifacts)、[Wildfrost Charms](https://wildfrostwiki.com/Charms)、[Risk of Rain 2 Item Stacking](https://riskofrain2.wiki.gg/wiki/Item_Stacking)、[Dead Cells Mutations](https://deadcells.wiki.gg/wiki/Mutations)、[Backpack Hero Relics](https://backpack-hero.fandom.com/wiki/Relics)、[Chrono Ark Relics](https://chronoark.fandom.com/wiki/Relic)、[One Step From Eden Artifacts](https://onestepfromeden.fandom.com/wiki/Artifacts)

## 5. 統合時に除外した主な重複

- 開始シールド、開始攻撃、開始速度、全カードcast短縮、勝利回復、勝利ゴールドだけの案は既存遺物と重なるため除外した。
- 「N枚使うとcooldown短縮」は三拍子リレーへ統合した。
- 「低HPで自動防御」「低HPで時間停止」は緊急投入口と薄明ペースメーカーへ分離統合した。
- 「完全防御で反撃」「完全防御でdelay」「完全防御でcooldown」は、戦闘テンポへの寄与が最も明確な全吸収検針器へ統合した。
- 「slot+1」だけの案は第四の予備架へ統合し、4枠目使用中の明示的な負担を加えた。
- 「自動投入の回数で成長」は、元カード強化の樹脂記憶塊と、投入抑制の廃熱プリンターに役割を分けた。
- 「状態終了時の追加効果」は臨界病理計へ統合し、自然終了だけを条件にした。
- 「アリーナhold割引」は持越し値札へ統合した。

## 6. 共通安全弁

1. 自動投入と遺物由来効果は、原則として遺物の手動カード回数を進めない。
2. `source_kind` と `source_relic_id` をイベントへ記録し、同じ遺物を再発火させない。
3. stopは連続4秒、reverseは連続3秒を初期上限にし、同系flowは加算せず長い残量へ更新する。
4. delay、haste、recast短縮は要求値ではなく、clamp後の実効変化量で発動判定する。
5. 遺物によるcast短縮は合計35%まで、実castは0.45秒以上。recast短縮は元値35%まで、実recastは4秒以上。
6. 反響・自動投入は `auto_depth`、戦闘回数、1update生成数の三重上限を持たせる。
7. 戦闘内charge、ICD、残り回数、予約slotは遺物ツールチップへリアルタイム表示する。
8. LANではホスト権威で判定し、遺物状態をsnapshot、reconnect、replayへ含める。
9. 発動順を `cooldown/status tick -> status expiry relic -> timeline flow -> due card resolve -> resolve後 relic` に固定する。
10. 遺物の戦闘内追加ゴールドは合計18G/戦までとする。

## 8. 実装基盤の提案

`RelicService.gd` のID別分岐を増やす前に、次を導入する。

- `RelicDef`へ `rarity`、`tags`、`effects`、`mode_scope`、`mutual_exclusion` を追加する。
- `RunState`へ遺物ごとのラン内永続状態を保存する `relic_state` を追加する。
- `BattleState`へcharge、ICD、発動回数を持つ `relic_runtime_state` を追加する。
- `card_committed`、`card_resolved`、`card_interrupted`、`damage_resolved`、`shield_changed`、`status_changed`、`timeline_shifted`、`cooldown_changed`、`slot_changed` の共通イベントを作る。
- `relic_trigger` と `relic_suppressed` をbattle eventへ記録する。
- LAN整合性ハッシュへ、データ駆動の遺物効果定義と効果resolverのバージョンを含める。

バランステストでは勝率だけでなく、平均戦闘時間、実効delay/haste秒数、stop/reverse総秒数、interrupt成功率、自動投入数、slot 3/3占有時間、recast短縮総秒数、遺物発動回数を記録する。
