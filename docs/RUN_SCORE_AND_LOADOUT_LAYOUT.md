# 可変列ロードアウトと未戦闘を含む戦闘効率

2026-10-12 / QQ-0.35.0

## カード一覧

マップ、通常アリーナ、Web対戦の準備画面で`LoadoutInventoryGrid`を共有する。画像を上、所持数・装備数をその下、ホバー時の装備・売却をさらに下へ配置する。装備デッキの22px解除ボタンと、最後の1枚の保護・準備ロックは変えない。

- 列数はカード枠の実際の最小幅と一覧枠の幅から決める。表示解像度に対する小さすぎるセルも避け、最大6列にする。
- ウィンドウの拡大・縮小に追従し、縦スクロールバーの余白は最初から予約する。列数を毎フレーム走査するのではなく、寸法変更時にまとめて再計算する。
- 横バーは表示しない。横スクロール無効モードは子グリッドの最小幅で親枠を固定してしまうため、バー非表示モードとセル幅の検証を組み合わせる。
- 操作欄の予約サイズはアイコン・テーマの初期設定後に確定する。非表示から表示へ切り替えても枠の高さを変えない。
- 開発者モードでマップ、アリーナ、戦闘へ移動できる既存ショートカットを引き続き使用できる。

## 戦闘効率

1戦の効率と重みは従来どおり。

```text
1戦の効率 = clamp((基準時間 * 2 - 戦闘時間) / 基準時間, 0, 1)
戦闘効率点 = round(1500 * 完了記録の効率加重合計 / 評価対象の総重み)
評価対象の総重み = max(戦闘記録の総重み, ランの予定ルートの総重み)
```

通常戦1.0、エリート1.25、危険地帯の各ウェーブ1.15、ボス1.5を維持する。未戦闘・戦闘時間0以下は分母に含めるが、分子への加点は0。未戦闘分の時刻や勝利を捏造して履歴に追加する変更ではない。

通常ランは各ステップの選択済み/完了したノードを対象にする。まだ選択していないステップは、最も軽いルート1つの重みを使う。回復・ショップ・イベントなどは戦闘分母に含めず、選ばなかった分岐も重複計上しない。選択した危険地帯は未戦闘ウェーブも含めた全ウェーブを対象にし、撤退による未戦闘分を0点とする。

アリーナは戦闘記録の重みに、必要勝利数までの残り勝利数を加えたものを分母にする。敗北を重ねても未戦闘の残り勝利数を減らさない。完走後は従来どおり記録された全試合の加重平均になる。無限ランは現在生成されている全周期のステップを対象にする。マップのない旧形式データは記録された戦闘だけで計算する。

標準の7ステップで軽いルートを選ぶ場合、総重みは`1 + 1.25 + 1 + 1.5 = 4.75`。最初の通常戦1つを基準時間以内に終えた時点の効率は`round(1500 / 4.75) = 316`で、残り未戦闘を除外して1500点にすることはない。全戦を基準時間以内に終えれば従来どおり1500点になる。

ラン結果の評価バー・合計・ランク・ランク実績は、共通の`RunScoreResolver`からこの値を受け取る。戦闘効率の見出しにも計算ルールのツールチップを付けた。過去に受け取った実績報酬を取り消す変更はしない。

## 関連検証

`LoadoutInventoryGridSmoke`は列数の拡大/縮小、セルの実最小幅、横にはみ出さないこと、スクロールバーによる振動を検証する。`LoadoutHoverSmoke`は操作欄と枠の寸法、装備解除、再利用、準備ロックを検証する。

`RunScoreSmoke`は7/14/21/28ステップの未到達分、分岐の重複回避、戦闘時間0、危険地帯の未戦闘ウェーブ、アリーナ、満点の完走、結果画面のアニメーションを検証する。`ProgressionTierSmoke`のSランク用データは、ボスだけを倒したことにせず、前のルートの戦闘記録も揃えて検証する。

ブラウザ検査はWeb Layout Review専用ビルドと`tools/web_inventory_grid_review.mjs`、`tools/web_loadout_hover_review.mjs`を使う。実画像・セル位置・列数・横バー・ホバーと装備操作・早期終了時の結果点数を確認し、テスト用の画面やブリッジは本番に含めない。

今回の確認: 関連Godotテスト14件、グリッド表示12画面/サイズ、実マウスの装備操作6画面/サイズ、一般レイアウト18画面/サイズを通過。ブラウザ1920px幅はマップ3列/アリーナ2列、960px幅はマップ2列/アリーナ1列となり、早期終了の結果バーでも316点を確認した。
